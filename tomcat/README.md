# Tomcat

Apache Tomcat 11.0 (`tomcat:11.0.27-jre21-temurin-noble`: Java 21 LTS, Ubuntu 24.04) as a single-replica Docker Swarm service, `tomcat-app-service`. `server.xml`, a landing page and a `/ping` health page ship as Swarm configs; `application.properties`, which holds the database password, ships as a Swarm secret.

| Item | Value |
|---|---|
| Ports (Swarm ingress) | `8085` app, `8081` health (`/ping/`). `8080` is avoided: it's cAdvisor's |
| Placement | `node.role == worker` (`gru` or `cass`), to keep load off `scarlet` |
| Network | Joins the database stack's `db_net`, so `jdbc:postgresql://softcraftmark:5432/appdb` resolves (`postgresql` works too, as an alias) |
| Terraform state | Terraform Cloud, org `softcraft`, workspace `homenet-tomcat` (Local execution mode) |
| Credentials | `app_db_password` from 1Password item `homenet-tomcat` (vault `private`) via `op.env` |
| Depends on | `database/` deployed first (`db_net` must exist) |
| Image reference | An exact patch tag (`tomcat_image`, validated): readable in `docker service ps` and pulled by whichever node runs the task. Floating tags like `11.0-…` are rejected, so the running build only changes when the tag in code does. (A `docker_image` local image ID fails on workers with `No such image`) |

## Files

| Path | Purpose |
|---|---|
| `main.tf` | Configs, secret, service. Templates rendered with the built-in `templatefile()` |
| `variables.tf` | Inputs with validation (ports, replicas, password) |
| `outputs.tf` | Service name and published port |
| `templates/*.tftpl` | `server.xml` (app connector + a separate health connector), `index.html`, `health_ping.json`, `application.properties` |
| `op.env` | `TF_VAR_app_db_password=op://private/homenet-tomcat/password` |
| `Makefile` | `create-secret`, `check-secrets`, `db-role`, `plan`, `apply`, `destroy` |
| `scripts/create-db-role.sh` | Creates or updates the PostgreSQL role; password on stdin only |

## First deployment

1. Create the 1Password item. The password is generated by 1Password, never shown, never passed as an argument:
   ```zsh
   cd ~/AI_Workspace/Projects/HomeNet/tomcat && make create-secret && make check-secrets
   ```
2. Switch to the Terraform Cloud backend. The old local `terraform.tfstate` is empty (0 resources). `terraform init` asks whether to copy it; answer `yes` (or move the two `terraform.tfstate*` files aside first). This step needs a terminal, so run it without `-input=false`:
   ```zsh
   terraform init
   ```
   If Terraform Cloud creates the `homenet-tomcat` workspace in **Remote** execution mode, switch it to **Local** (Settings → General): the Docker context only exists on `medusa`.
3. Create the database role Tomcat logs in as, once the `database/` stack is up. The password goes from 1Password to `psql` on stdin only, never on a command line; running it again resets the password:
   ```zsh
   make db-role
   ```
4. Plan and apply. `make apply` doesn't prompt:
   ```zsh
   make plan
   ```
   ```zsh
   make apply
   ```
5. Verify:
   ```zsh
   curl -s http://scarlet:8081/ping/ && curl -sI http://scarlet:8085/ | head -1
   ```

## Operations

| Target | What it does |
|---|---|
| `make create-secret` | One-time: creates `op://private/homenet-tomcat/password` with a generated 32-character password |
| `make check-secrets` | Shape of the 1Password value; never printed |
| `make db-role` | Creates or resets the `tomcat_user` role in `appdb` on the PostgreSQL service (`cass`) with the 1Password password (`scripts/create-db-role.sh`) |
| `make plan` / `make apply` | Through `op run`; `apply` is `-auto-approve` |
| `make destroy` | Removes the service, configs and secret. Prompts for `yes` |

Changing a template or the password creates a new config or secret (content-hashed names) and rolls the service.

## Notes

- **Upgrading Tomcat.** Pick the newest `11.0.NN-jre21-temurin-noble` tag on Docker Hub, set `tomcat_image`, then `make plan` and `make apply`. For exact pinning, `tomcat:<tag>@sha256:<digest>` also works, at the cost of the digest showing in `docker service ps`.
- **No data.** Tomcat is stateless here: it serves the landing page and the health page. `application.properties` is on the classpath for a future webapp.
- **The old `app_db_password` default is in git history** (commit `a1ef232`, local only). It's gone from the code; rotate it if it was ever used anywhere.
- **Clutter to remove:** `chat.json` (an empty Copilot chat export) and `templates/server.xml.old`, `server.xml.old2`, all tracked: `git rm tomcat/chat.json tomcat/templates/server.xml.old tomcat/templates/server.xml.old2`. After step 2, the local `terraform.tfstate*` files can be deleted too.
